# Writing rules

> PRD, weekly update, decision-record conventions.

## PRD format
<!-- Sections, length, examples. Common pattern: problem → users → success → solution → risks → out-of-scope. -->
Use: premise → category/user problem → editorial rule → current scope → success
criteria → risks/tensions → non-goals. Keep the singular verdict and the
`EMPTY` state explicit.

## Weekly update format
<!-- Who reads it, what they need, length cap. -->
For Laurent: outcome first; changed files or product state; evidence learned;
open judgment; next reversible action. Keep it short enough to scan.

## Decision record
<!-- Mirrors decisions/_SCHEMA.md. Stay consistent. -->
Use the canonical schema. Every evidence and explicitly-not-doing row carries
one honest provenance tag, and every decision names an observable reversal
condition.
