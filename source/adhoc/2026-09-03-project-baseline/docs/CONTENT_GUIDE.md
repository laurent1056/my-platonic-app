# Content Guide

The CSV is the source of truth for what the site says.

## Voice

- calm
- specific
- unsentimental
- non-promotional

Write like a museum placard crossed with a mechanic's note.

## Preferred field intent

### `Form Definition`
Define what the object is in functional terms.

### `Form Statement`
Shorter articulation of the category's governing idea.

### `Card Snippet (Why this ends the search)`
Concise front-page summary. This is the preferred one-liner source.

### `Core Reasoning` / `Core_Reasoning`
The main argument for the declaration or empty verdict.

### `Key Disqualifiers` / `Key_Disqualifiers`
Explain why the common alternatives fail.

### `Maintenance / Replacement Cycle`
Describe what, if anything, wears and on what cadence.

### `Permanence Mechanism`
Name the mechanism that makes long-term ownership viable.

### `Admission Test`
Use for explicit proof criteria or checklist-style evidence when available.

### `Failure Modes`
State how the product or category fails first, without spin.

### `Notes`
Internal or contextual guidance. These still surface in `Source Fields`, so avoid junk text.

## Hard rules

- No shortlists in a single category.
- No hedging like "X or Y".
- If a category is unresolved, say so directly.
- If a product depends on replacement or repair, say that plainly.
